# Handoff: pramana three-agent evaluation and the full-corpus campaign

Written 2026-11-01 by the Claude Code session that did the work below, so the same run can be
resumed on another machine. Everything here is in the working tree, nothing was committed
(last commit on `main` is `f803152`). Read this file first, then `docs/agent_eval.md` and
`docs/pramana_flow.md`.

## 1. Goal and where things stand

The user's goal: learn a pramana knowledge base (KB) from the FPL'26 contest benchmark DCPs,
then evaluate three agents on the same context, KB and recipes:

1. the official AMD/Xilinx FPL'26 contest agent (the baseline),
2. maya,
3. PACT (FDAgents).

Done so far:

- A 3-design campaign `campaigns/dev1/` (amd_mini-isp, finn_radioml, logicnets_jscl) ran all
  stages and compiled a KB: `campaigns/dev1/out/maya/{context.md,recipes.tcl,knowledge.json}`
  and `campaigns/dev1/out/adapters/pact/{cases.yaml,context.md}`.
- All three agents were evaluated with that KB on a seen design (amd_mini-isp) and an unseen
  one (vexriscv_re-place), with two models: `deepseek/deepseek-v4-pro` and
  `deepseek/deepseek-v4-flash` (12 cells, all valid). Results in section 4.
- A 14-design campaign `campaigns/full1/` was started and **stopped after 6 minutes** on
  2026-11-01 (this machine is shared and could not parallelise enough). It must be rerun on the
  new machine. That is the next step; afterwards the user will name the DCP(s) to evaluate on.

Vivado concurrency: `pramana/vivado.py` caps live Vivado processes machine-wide at
`PRAMANA_MAX_VIVADO` (default 4) via lock files in `PRAMANA_SLOT_DIR` (default
`/tmp/pramana_vivado_slots`), each run with `threads` (default 4). A run also waits until free
memory is at least `min_free_mem_gb` (16) plus `2.5 + 0.09 * dcp_mb` GB. On a bigger machine
raise `PRAMANA_MAX_VIVADO` and pass `--workers N` to `pramana`. Agent evaluations hold one slot
each for their whole budget plus 15 min grace. The user's own limit was 3 agents at once.

concluding anything.

## 5. How the three agents consume the KB (summary; details in SOURCE.md files)

- **official** (`consumers/official/dcp_optimizer.py`, flags `--kb hand|none|pramana --kb-dir
  --run-dir --time-budget-s --base-url --dry-run-prompt`): pramana variant = protocol-only system
  prompt + `::pramana::` procedure reference + `context.md`; `recipes.tcl` is sourced through
  `run_tcl` after every `vivado_open_checkpoint`; a time budget was added (upstream has none)
  with one final "save and reply `final design saved`" turn. Upstream also has a **50-iteration
  safety cap**: a fast model hits it before the hour and the agent exits 1 with "did not complete
  successfully", but the output DCP is written and is scored normally.
- **maya** (`consumers/maya/maya.py`, `pramana.maya_eval --kb pramana --provider openrouter`):
  same prompt split, sources `recipes.tcl`, banks the best checkpoint itself. Its OpenRouter
  default model is deepseek-v4-pro; always pass `--model` explicitly.
- **PACT** (`consumers/pact/`, `pramana.pact_eval --kb pramana --bundle
  campaigns/<c>/out/adapters/pact`): PACT's loader rejects raw Tcl, so the KB enters as typed
  cases (`cases.yaml`, from `pramana.adapters.write_pact_cases`) plus `context.md` and the
  matched cases injected as an advisory `learned_prior` into the Decision LLM's state (the
  `[pramana]` patch; env `FDAGENTS_PRAMANA_CONTEXT`). Verified in `run/memory.json`
  (`learned_prior` present, matched cases scored).

Commands (from the repo root, after `source ~/.config/pramana/llm.env`):

```bash
export MAYA_RAPIDWRIGHT_PATH=/path/to/built/RapidWright
M=deepseek/deepseek-v4-flash; B=fpl26_contest_benchmarks; C=campaigns/dev1; D=vexriscv_re-place
python3 -m pramana.official_eval --dcp $B/${D}_2025.1.dcp --out $C/official_eval/$D.pramana.flash --kb pramana --bundle $C/out/maya --budget-s 3600 --model $M
python3 -m pramana.maya_eval     --dcp $B/${D}_2025.1.dcp --out $C/maya_eval/$D.pramana.flash     --kb pramana --bundle $C/out/maya --budget-s 3600 --model $M --provider openrouter
python3 -m pramana.pact_eval     --dcp $B/${D}_2025.1.dcp --out $C/pact_eval/$D.pramana.flash     --kb pramana --bundle $C/out/adapters/pact --budget-s 3600 --model $M
```

Output dir names are `<design>.<kb>[.<tag>]`; the table script shows the tag-less pro runs
and the `.flash` runs side by side with a model column. Each `result.json` has the agent's own
bookkeeping plus `input_wns`, `output_wns`, `output_valid`, `final_wns`, `d_wns`, `valid`.

Queue pattern used (max 3 agents at once, 150 s between launches so Vivado and the MCP servers
come up before the next count):

```bash
agents() { ps -eo args | grep -E "^[^ ]*python[0-9.]* .*(maya\.py|dcp_optimizer\.py|FDAgents\.agent)" | grep -v grep | wc -l; }
wait_slot() { while [ "$(agents)" -ge 3 ]; do sleep 30; done; }
```

## 6. Pitfalls that each cost a run (do not rediscover)

1. **PACT refuses every LLM call without a pricing entry** for the model
   (`cannot enforce a cost cap without model pricing`). `pact_eval` fetches USD/1K-token rates
   from OpenRouter's `/api/v1/models` and writes `llm.pricing` into its config override; pass
   `--pricing IN,CACHED,OUT` if offline.
2. **PACT's selector stage allows 2000 output tokens and one turn.** A reasoning model spends
   them on hidden reasoning and the run dies with `llm_decision_unavailable`. The override sets
   `max_output_tokens` 8000/6000/8000 for the three stages, and the patched copy adds
   `react.selector_turns: 3` and `react.retry_invalid_decisions: true`.
3. **PACT's `clock_tighten` rewrites the contest clock period** and reports WNS against the new
   period (vexriscv left at 1.986 ns, self-reported -0.103/-0.127). Never use an agent's
   self-reported WNS; `measure_dcp(..., clocks=input_clocks)` re-imposes the input periods. All
   drivers do this.
4. **The agents' persistent Vivado outlives the agent.** The MCP servers start `vivado -mode
   tcl` on a pty (its own session), so after the agent exits Vivado keeps running at 100% CPU
   forever (three such orphans ran 29 h on this machine). All three drivers now call
   `pramana.vivado.reap_under(out)` after the run. On the old machine the orphans
   (pids 2336940 2336970 2434378 2434416 3378959 3378988) still need `kill` by the user.
5. **PACT uses the OpenAI Responses API** with `reasoning.summary`,
   `include=reasoning.encrypted_content`, `store=False`. OpenRouter serves this for
   deepseek-v4-pro and deepseek-v4-flash (both checked with a probe); check any other model first.
6. **`pkill -f` / `pgrep -f` with a pattern that matches your own shell** kills or deadlocks
   the queue. Anchor patterns (`^python3 -m pramana.pact_eval`) or use the `[F]DAgents` trick.
7. **maya/official RapidWright init** failed on a hard-coded `<repo>/RapidWright/jars` path; the
   servers now honour `RAPIDWRIGHT_PATH` (set by the drivers from `MAYA_RAPIDWRIGHT_PATH`).
8. **`pramana all` with zero designs runs through every stage doing nothing** (happened when
   corpus paths were wrong). It should refuse; not implemented. Check `designs.json` after `init`.
9. Log timestamps in agent logs are local time; the first "stuck" diagnosis was a UTC mix-up.

## 7. Resuming the campaign on the new machine

```bash
# 1. fix the two machine-specific paths
#    pramana/config.py  VIVADO_SETTINGS   pramana/corpus.py  DEFAULT_SOURCES
# 2. optional: raise the Vivado cap
export PRAMANA_MAX_VIVADO=8          # or whatever the machine allows (16 GB per big-design run)
# 3. init over all 14 designs (the corpus skips *_v2*), then run every stage
python3 -m pramana init full1 --workers 8 --threads 4
python3 -m pramana all full1 > campaigns/full1/all.stdout 2>&1 &
# progress: campaigns/full1/pramana.log  ("=== <stage> done in Ns ===")
# stages: space profile probe baseline prune search discover confirm distill compile
# resume after an interruption: python3 -m pramana all full1 --from <stage>
```

Time expectations from dev1 (3 small designs, 4 live Vivados): baseline 2.7 h (66 runs),
prune 8 min (LLM), search 1.1 h (4 rounds), discover 26 min (LLM agents), confirm 1.7 h,
distill 1 min, compile instant. full1 has 14 designs including boom_soc (145 MB) and
ispd16_example2 (152 MB) whose single runs take hours, so plan for days unless the cap is raised.
`run_timeout_s` is 4 h per Vivado run.

When `=== compile done` appears, the bundles are `campaigns/full1/out/maya/` and
`campaigns/full1/out/adapters/pact/`. Then ask the user which DCP(s) to evaluate on, and run the
three drivers with `--bundle` pointing at full1 (section 5), writing under
`campaigns/full1/{official,maya,pact}_eval/`, and build the table with
`scripts/agent_eval_table.py full1`.

## 8. Pipeline recap (details: docs/pramana_flow.md)

S0 space (framework spec per Vivado version/part, probed once) → S1 profile (features per DCP) →
S2 baseline (per-design reference runs, Vivado) → S3 prune (LLM analyst + critic via Claude Code)
→ S4 search (bandit over directive chains + tests + audits, Vivado; LLM report per round) →
S5 discover (LLM agent with `./trial`, Vivado) → S6 confirm (replay/transfer/funccheck, Vivado)
→ S7 distill (`kb.json`, leave-one-family-out) → S8 compile (`out/maya`, `out/mithya`,
`out/adapters/{latch,pact}`). Shared `store/` keyed by DCP md5; unit is ΔWNS in ns; validity =
routed, 0 route errors, WHS ≥ 0, WPWS ≥ 0.
